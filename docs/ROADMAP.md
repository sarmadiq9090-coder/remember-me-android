# Roadmap: Remember Me for Android 0.2.0 → 1.0.0

Source: the owner's PRD ([PRD-owner-2026-11-14.md](PRD-owner-2026-11-14.md)), reviewed on 2026-11-14 by a
council of five (R reliability / Android platform, P product and UX, N Arabic NLP, S privacy and
security under OWASP MASVS v2 and ISO/IEC 29100, X devil's advocate) under the owner's «اسئل المجلس و
نفذ». The decision record is brain D-079. The PRD is accepted with the amendments below. An Arabic
summary for the owner is at the end.

Facts this plan respects: Kotlin and Compose, minSdk 26, targetSdk 36; a sideloaded APK for the owner
only; **no INTERNET permission, and it stays that way**; the data is the Windows app's `data.json`
(the PRD's "database" means this file and `data/Store.kt`, not SQL); no emulator (this PC has no
hypervisor) and no device lab. The only real phone is the owner's. Releases are tested on the JVM
with Robolectric, then on the owner's phone.

Nothing in this plan promises that every reminder arrives on every phone. Android, the phone maker
and the user's settings can delay or block an alarm. What we can promise is that the app schedules
correctly, notices when something blocks it, and says so.

## 2. The release gate (every release)

PRD §9.3 says no release may ship unless the exact-alarm and notification permissions were tested
"on the target Android version". Here that means, honestly:

1. **JVM gate.** The full JUnit and Robolectric suite passes. The alarm, permission, notification
   and receiver tests run at several SDK levels with `@Config(sdk = [26, 29, 31, 33, 34, 36])`.
   That covers minSdk, the exact-alarm permission (31), `USE_EXACT_ALARM` and runtime notification
   permission (33), full-screen intent limits (34) and the target (36). Robolectric is a model of
   Android, not Android: we say "tested on Robolectric API N", never "tested on Android N".
2. **Build checks.** `lintRelease` reports no issues; `apksigner verify`; 16 KB alignment; the
   permission set equals the 0.1.1 set (a test fails on INTERNET or any new permission); APK size
   inside the budget (§7); SBOM and SHA-256 written.
3. **Independent bug hunt** by an agent that did not write the code, with a failing test per
   finding. Every S1/S2 is fixed before the build goes to the owner.
4. **Owner phone checklist** (§5), on a pre-release APK installed over his current version. The
   release notes name the phone and its Android version. Nothing is claimed for any other phone.

**Blocking defects** (no release while any is open): a test that could lose a reminder fails; any
unintended duplicate alert; a failed data migration; a valid backup that will not restore; an
essential permission not checked on the owner's phone; a critical RTL or accessibility defect
(TalkBack cannot reach «تم», clipped Arabic at 200 % text).

## 3. Scheduling API per kind of moment (PRD §16)

Today the engine sets one `setAlarmClock()` for the next moment of any kind (D-004). From 0.2.0 the
plan has two slots, each one `PendingIntent` with a fixed request code and `FLAG_UPDATE_CURRENT`, so
re-arming replaces and never adds. There are no per-reminder alarms, which also keeps the app far
below Android's limit of 500 alarms per app.

| Moment | API | Trade-off |
|---|---|---|
| A due reminder (one-time, or a repeat's occurrence) | **Slot A: `setAlarmClock()`** | Exempt from Doze and app standby; the user picked that minute. Cost: the status-bar alarm icon and "next alarm" on the lock screen and in quick settings show it. The Health screen explains the icon. |
| A snooze | **Slot A: `setAlarmClock()`** | A snooze is a new due time. Repeated taps re-arm the same slot, so alerts never pile up. |
| A reminder days ahead | **Slot A: `setAlarmClock()`** for the nearest due time only, with no wake-ups in between | No battery cost while waiting. The alarm icon stays visible while any timed reminder is ahead; that is the price of not missing it. A "checkpoint" alarm to shorten the icon time was rejected: in the restricted bucket a checkpoint can be held for up to a day. |
| An early notice | **Slot B: `setExactAndAllowWhileIdle()`** | No alarm icon. In Doze, allow-while-idle alarms are limited to about one per 9 minutes per app (the documented limit varies by version), so an early notice can come a few minutes late. The due time itself is in slot A and does not depend on slot B. |
| "Sound again" (remind again, 2/5/15 minutes, at most 6) | **Slot B: `setExactAndAllowWhileIdle()`** | The reminder is already on screen and in the shade; a re-alert a few minutes late in deep sleep is acceptable. It no longer moves the "next alarm" shown by the system to two minutes from now. |
| Untimed items | **No alarm.** Housekeeping (trash purge, the widget's day change) uses inexact `setWindow(RTC, local midnight, 1 hour)`, non-waking | Runs when the phone is awake anyway. It is also done on every app start and every engine run. Untimed items show in the list and the widget, never as alerts. |
| Exact-alarm access denied | **Both slots: `setAndAllowWhileIdle(RTC_WAKEUP)`** | No permission needed. It can be minutes late, and much later in the restricted bucket. The red banner and the Health screen say "reminders may arrive late". Re-armed at once when access returns (the permission broadcast, and the check on resume). |

Notes for R and S:
- On Android 13+ the app holds `USE_EXACT_ALARM`, granted at install. The Android docs say the user
  cannot revoke it; Android 12 and 12L use `SCHEDULE_EXACT_ALARM`, which the user can revoke. Both
  are checked on every engine run and on every return to the app. The owner's phone confirms which
  case applies.
- D-004 says `USE_EXACT_ALARM` keeps the app out of the restricted bucket. That is not verified on a
  phone. 0.2.0 reads the bucket (`UsageStatsManager.getAppStandbyBucket()`, no permission needed for
  the app itself) and shows it, and the checklist puts the app in "Restricted" on purpose.
- Battery: no periodic jobs, no WorkManager polling, no foreground service. One wake per due moment.
- X dissented (vote 4–1): two slots double the code that can fail. Adopted as conditions: slot A
  never reads slot B's state, and a test kills slot B (cancels it, makes it throw) and shows every due
  time still fires.

## 4. Quick Add Arabic parser (0.3.0)

Decision (vote 5–0): **port the Windows parser** (`src/core/natural-dates-ar.js`, `natural-dates-en.js`,
`natural-dates.js` in the Remember-Me repo) to Kotlin, for parity. It already does what the PRD asks.
It normalises letters (أ/إ/آ → ا, ى → ي, ة → ه, چ → ج, گ → ك), diacritics, tatweel and Arabic-Indic
and Persian digits. It reads standard Arabic plus Iraqi, Gulf and Levantine speech. It never guesses
AM/PM, the week or a missing time. Licence: it was published on main under MIT on 2026-11-06 (commit
84f82fa), before D-051, and the owner holds the copyright, so a port is clean under any licence
outcome.

Scope for 0.3.0 (the Windows coverage, nothing more):
- Days: اليوم، الليلة، غداً/بكرة/باچر، بعد بكرة، weekday names with الجاي/القادم/هذا, «الأسبوع الجاي».
- Relative: بعد ساعة/ساعتين/نص ساعة/N دقائق/يوم/أسبوع/شهر، كمان، خلال.
- Times: «الساعة 9»، 7:30، «خمسة ونص»، «4 إلا ربع»، ordinal hours, and parts of the day (الفجر، الصبح،
  الظهر، العصر، المغرب، المسا، العشا، الليل، نص الليل).
- Repeats: كل يوم/يومياً، كل خميس، «كل أحد وأربعاء»، كل N أيام/أسابيع، كل يومين، كل شهر، كل سنة.
- English when the text has no Arabic letters (the Windows rule), whatever the UI language.
- Not in 0.3.0: Hijri dates, dates such as «15 رمضان», «كل N ساعات» (Android-only repeat; a later
  addition with its own tests), and spelled-out minutes beyond the Windows set.

Rules:
- **Never invent a date.** A bare number is a time only after «الساعة»/«على», with minutes, with a part
  of the day, or right after a day word. «اشتري 5 كيلو» keeps its number. A past day («الخميس
  الماضي») stays in the title.
- **Always a preview.** Nothing typed is saved with a date until the preview chip has been shown.
  Unclear phrases ask, with at most 4 dated choices as chips: AM or PM («meridiem»), this week or next
  («day»), no time given («time»: 9:00, 12:00, 18:00), both («choose»), or that time has passed
  («past»: the next one). If nothing is understood, the whole text becomes the title with no date.
  The full editor is always one tap away.
- Display stays Western digits (brain D-012), even when the user typed ٥.

Acceptance (measurable):
- A golden file made by running the Windows `parseWhen()` (a new `tools/quickadd-golden.cjs`, like
  `windows-golden.cjs`) over at least 600 phrase × "now" cases (fixed Monday and Friday times, week
  start Saturday, Sunday and Monday, and a DST zone). The Kotlin result equals it in every case:
  title, `dueAt`, `ask`, `options`, repeat fields.
- A "no date" corpus of at least 200 realistic invented titles (shopping, names such as «خميس» and
  «جمعة» as people, Quran surah names, prices, room numbers, phone-number-like digits). Gate: **zero
  invented dates** (the D-071 false-flag rule).
- A UI test shows no save path that stores a parsed date without the preview.
- Entry points: the Home add field, the launcher shortcut, and the widget's add button.

## 5. Device compatibility, honestly

- **Here (automated):** the JVM gate in §2, with Robolectric shadows for the alarm manager, the
  notification manager, the exact-alarm permission and the boot and time broadcasts.
- **The owner's phone, every release:** the checklist below, about 30 minutes, run from a
  pre-release APK installed over the current version. Results go into `docs/COMPATIBILITY.md`
  (created in 0.2.0).
- **The matrix** lists only devices actually tested. Columns: date, app version, maker and model,
  Android version and skin version (for example One UI 6.1, HyperOS 1.0), then one result per test:
  pass, fail or not run. It starts with one row: the owner's phone. Rows are added only from a real
  test or a compatibility report a real user chose to share.
- **«تقرير التوافق» (opt-in, 0.2.0):** a Settings row builds a short report only when tapped, shows
  all of it on screen, and offers Android's share sheet (`ACTION_SEND`, text). No file is written to
  shared storage and there is no network code.
  - Included: report format `compat-report@1`; app version and versionCode; `Build.MANUFACTURER`,
    `Build.MODEL`, Android release and SDK level; UI language (ar/en); each Health check (notifications,
    channel importance and sound, exact access and which permission, full-screen, battery
    optimisation, background restriction, standby bucket, Do Not Disturb, notification volume zero,
    boot seen since the last restart); the last «اختبر التنبيه الآن» result per part (pass, fail,
    unknown) and its measured delay in seconds; the median and worst alarm lateness from the local
    scheduling log; the number of timed reminders as a band (0, 1–10, 11–100, over 100).
  - Never included: titles, notes, categories, tags, reminder times, task ids, the time zone, Android
    ID, IMEI, serial, accounts, file paths, the IP address, location, contacts.
  - A test checks that the report never contains any title, note or id from a sample data file.

### Owner phone checklist for 0.2.0

Write down the phone model and Android version first. Each item is pass, fail or skipped.

1. Install 0.2.0 over 0.1.1: every reminder is still there, and the count in the Health screen
   equals the count before.
2. Reminder Health: every item is green, or each red item has a button that opens the right
   system screen. Fix it there, come back: the status updates without restarting the app.
3. «اختبر التنبيه الآن» with the screen on: the notification, sound and vibration, and the «تم» and
   «أجّل» buttons. Then again with the phone locked: the full-screen reminder screen appears (or the
   result says it is not allowed and why).
4. Two reminders in the same minute and a third one minute later: each one sounds once, none twice.
5. Overnight: phone unplugged, screen off for at least 6 hours, a reminder in the morning. It
   arrives; write down how late (the Health screen shows the measured delay).
6. Restart the phone with a reminder 5 minutes ahead and do not open the app: it sounds on time.
7. Snooze 10 minutes from the notification: it sounds once, 10 minutes later. For a repeating
   reminder the next occurrence is unchanged.
8. Swipe a due notification away: it comes back quietly. «تم» clears it for good.
9. Turn the app's notifications off in Android settings: Health turns red and the banner shows.
   Turn them back on and return: green.
10. Set the app's battery use to "Restricted" (or the maker's equivalent): Health shows it in red
    and says whether it is an Android setting or the maker's. A reminder 10 minutes ahead: write down
    whether and when it came. Then set it back.
11. Change the time zone by hand (Baghdad to Dubai): a one-time reminder keeps its moment; a daily one
    follows the D-012 rule; nothing sounds twice. Change it back.
12. Move the clock forward past a reminder: it sounds once (or shows as overdue). Restore automatic
    time.
13. Force stop the app, then open it: overdue reminders are listed and future ones are armed again
    («آخر فحص» updates). Android does not run a force-stopped app's alarms until it is opened; the
    app cannot change that.
14. Backup: export, then import the same file. The summary shows the right counts. «إلغاء» changes
    nothing. «استعادة» restores, and a safety copy is listed.
15. «تقرير التوافق»: the preview has no reminder titles, and the share sheet opens.
16. A quick look in English and at the largest text size: nothing is cut off on the Health screen.

## 6. Licence path

Brain D-051 made Remember Me closed source, and `DECISIONS.md` D-014 applied it here. The PRD says
«مفتوح المصدر». The manager reads the PRD as the owner's stated direction for **the Android app
only**. The repository is made ready, but nothing is published and no licence is granted until the
owner says «انشر», as D-076 required for Scan Kiwi. The Windows app stays under D-051.

**Added now (0.2.0, by the app agent):**
- `docs/OPEN-SOURCE-PROPOSAL.md`: the proposal (Apache-2.0, the reasons from D-076: matches AndroidX
  and Kotlin, patent grant, no trademark grant), the exact LICENSE, NOTICE and `REUSE.toml` contents
  to be added on «انشر», the pre-publication audit list, and the order of steps. Its first line:
  "This is a proposal. It grants no licence. Remember Me for Android is proprietary until the owner
  approves publication."
- `SECURITY.md`: report privately to support@fastkiwi.app (GitHub private vulnerability reporting once
  a public repository exists); what is in scope; no bounty. It is true whether the code is open or
  closed.
- `CONTRIBUTING.md`: "Issues are welcome once the repository is public. Pull requests are not accepted
  for now." This keeps the one-writer rule and avoids a CLA.
- `.gitattributes`: `* text=auto eol=lf`, binary for png, jpg, ttf, jar and webp.
- README, licence line: "Proprietary FastKiwi software (D-051). Publishing under Apache-2.0 is
  proposed (D-079) and needs the owner's approval; until then no licence is granted." The existing
  `LICENSES/Apache-2.0.txt` stays, because it covers third-party components.

**Not added now, and why:**
- `LICENSE` and `NOTICE` at the root: GitHub and every scanner read them as the project's licence.
  That would be a claim the owner has not made.
- `REUSE.toml`: it is itself a licence declaration for every path. Its draft lives inside the
  proposal file.
- Per-file SPDX headers: never. On «انشر», `REUSE.toml` covers the files by path, so no source file
  is touched twice and no header can be wrong in the meantime.

**On «انشر»:** add LICENSE (Apache-2.0), NOTICE and REUSE.toml; `reuse lint` passes; D-014 is marked
superseded; the README licence section is updated. A blocking audit as in D-076 comes first:
secrets (the keystore never in git), personal data (paths, names, the owner's quotes), screenshots
(synthetic data only), and **code ported from the Windows app**: each port is listed with its source
commit date. Code published under MIT before 2026-11-09 (for example `repeat.js` and the Quick Add
parser) is clean. Any port of later Windows code needs the owner's explicit approval, because it
would publish proprietary Windows code. Then the repository, release and site steps of D-076, through
the one GitHub writer.

## 7. Releases

Each release ships only when its criteria and the gate in §2 pass. APK size: 0.1.1 is 2.03 MB.
Budget: no more than 15 % growth per release without a written reason in the CHANGELOG, and a hard
cap of 4 MB before 1.0.

### 0.2.0: trust and reliability

**In:**
1. **Reminder Health** (it replaces «السماح بالعمل في الخلفية» and keeps its buttons). Checks:
   notifications; the reminder channel's importance, sound and vibration; exact alarms and which
   permission applies; full-screen; battery optimisation; background restriction
   (`ActivityManager.isBackgroundRestricted()`); standby bucket; Do Not Disturb; notification volume
   at zero; whether the boot broadcast arrived since the last restart (a boot newer than the last
   boot handled means the maker blocked it); the last engine run; whether the armed alarm equals the
   plan; how many reminders are scheduled; how many need attention. Each item is labelled
   **Android** or **the phone maker**. A «فحص الآن» button runs the engine and checks again.
2. **«اختبر التنبيه الآن»**: a synthetic reminder that is never written to `data.json`, through the
   real path (a slot A alarm 10 seconds ahead, the reminder channel, the full-screen intent, the
   «تم» and «أجّل» actions). The result lists each part: notification shown, alarm on time (measured),
   full-screen allowed, and buttons (detected); sound heard and vibration felt (the user answers yes
   or no). Never a single "success".
3. **Checks on resume**: on every return to the app (`ON_RESUME`) and on the exact-alarm permission
   broadcast, permissions are checked again, the banner and Health update, and the alarms are
   re-armed.
4. **Idempotent rebuild from the data**: two slots (§3); the plan is always computed from
   `data.json`, never from what Android holds. An occurrence key `taskId|dueAt` (already in the alert
   log) is the stable id of each occurrence.
5. **Duplicate prevention**: one loud alert per occurrence and "remind again" step, whatever runs the
   engine and however often.
6. **Local scheduling log**: a ring of the last 200 events (sync, arm, fire, boot, permission
   change, error) with the time, slot, armed time and lateness when fired. No titles, notes or ids.
   Shown as numbers in Health; never exported except as the bands in the compatibility report.
7. **Time, zone and reboot test suite** (below).
8. **Safe data migration**: before the first run of a new versionCode, a snapshot
   `safety/before-update-<versionCode>-<time>.json` (the newest 3 kept, listed beside the import
   safety copies). Phone settings (`Prefs`) get a schema number and a tested migration. A
   `data.json` from a newer format is kept untouched (A18).
9. **Backup verification and a summary before restore**: the file is decoded and checked fully
   before anything is replaced. The summary shows the source (Android or Windows) and date; whether
   the checksum was verified; active, repeating, done and trashed counts; notes kept; attachments
   dropped; hourly repeats. Then «استعادة» or «إلغاء». A safety copy is made before replacing.
10. **Better maker instructions**: steps per skin version (MIUI and HyperOS; One UI 5 and 6+ "never
    sleeping apps"; EMUI and HarmonyOS; ColorOS; Funtouch and OriginOS). Each step is marked
    «جُرِّب على هاتف» or «لم يُجرَّب بعد». The owner's own phone's steps are checked first.
11. **«تقرير التوافق»** (§5) and `docs/COMPATIBILITY.md` with its first row.
12. The licence-readiness files (§6) and the D-012 reference fix (A17).

**Out of 0.2.0:** merging backups (restore replaces, after a safety copy); encrypted backups (0.6.0);
direct boot; changing the D-012 time-zone rule; any new permission; Quick Add.

**Acceptance criteria:**
- Health never shows all green while notifications, the channel or exact access is off: all 8
  combinations of the three essentials are tested, and each shows red with its fix button.
- Health and the banner update within one resume after a permission change (lifecycle test), with
  no app restart.
- The alert test writes nothing: `data.json` is byte-identical before and after (test). The result
  has six parts, each pass, fail or unknown.
- Idempotence: a seeded property test runs at least 1,000 random sequences of engine runs and system
  broadcasts (boot, update, time set, zone change, permission change) over random data. After each
  sequence exactly one alarm is set per slot that has a moment, the alarm times equal the pure plan,
  and no occurrence step is announced loudly twice.
- Slot independence: with slot B cancelled or throwing, every due time still fires (test).
- Time suite, at least 30 named scenarios, all passing: clock forward and back by 1 hour and by 1
  day; zone moves among Asia/Baghdad, Asia/Dubai, Europe/Berlin, America/New_York,
  Australia/Lord_Howe (30-minute DST) and Asia/Kathmandu (+5:45); a DST gap and an overlap for
  daily, weekly, chosen-days, monthly (29, 30, 31 and the last day) and yearly (29 February); reboot
  with the alarm table cleared; app update; exact access revoked and granted again; two reminders in
  the same minute; 100 reminders within one minute; a failed write (disk full) with the alarm still
  set.
- Migration: an upgrade test from a 0.1.1 data file and settings keeps every task byte-for-byte in
  its typed and unknown fields, and writes the snapshot first. A `version: 2` file is never renamed
  or overwritten (test).
- Backup: the counts in the summary equal those in the file for at least 5 realistic invented
  files (D-071), Windows-made ones included. «إلغاء» leaves `data.json` byte-identical. A bad
  checksum, a newer format and a non-backup file are each refused with their own message.
- The permission set equals 0.1.1's (test). APK at most 2.35 MB.
- The gate in §2 passes, including the 16-item owner checklist (§5), with no fail in items 1–9.

## 8. Not planned (PRD §12, confirmed)

No required account or sign-in; no cloud sync, and none required later; no social or public sharing;
no online AI assistant; no ads and no subscriptions; no complex project-management board; no
location tracking, and none by default; no usage statistics that collect personal data; no
always-running background service just to stay alive; no marketing claim that every alert arrives
whatever the phone's settings. Also not before 1.0: location reminders (A11), sync (A12),
Google Play (D-019), an in-app updater (it would need the internet permission; see D-077 for the
Scan Kiwi route).

## ملخص بالعربي

- قَبِل المجلس وثيقتك مع تعديلات. أهمها: البيانات تبقى ملف `data.json` المشترك مع نسخة Windows، وأي
  حقل جديد لا يُضاف إلا بعد التأكد أن Windows يحتفظ به، وإلا نحذّرك قبل التصدير كما في «كل عدة ساعات».
- لا يوجد محاكي ولا مختبر أجهزة. نختبر على الحاسوب آلياً، ثم على هاتفك أنت بقائمة قصيرة (نحو 30
  دقيقة) قبل كل إصدار. جدول التوافق لا يذكر إلا الأجهزة التي جُرّبت فعلاً، ويبدأ بهاتفك.
- طريقة الجدولة: موعد التذكير والتأجيل بمنبّه كامل (تظهر أيقونة المنبه في الأعلى، وهذا طبيعي)،
  والتنبيه المبكر وإعادة الرنين بمنبّه أخف بلا أيقونة قد يتأخر دقائق في النوم العميق. إن مُنعت
  المنبهات الدقيقة نُظهر لك تحذيراً واضحاً.
- 0.2.0: شاشة «صحة التذكيرات» تفحص كل شيء وتفرّق بين إعداد أندرويد وإعداد الشركة المصنعة، وزر
  «اختبر التنبيه الآن» يبيّن أي جزء لم يعمل، ونسخة احتياطية تلقائية قبل كل تحديث، وملخص قبل أي
  استعادة، و«تقرير التوافق» تشاركه بنفسك إن أردت، بلا أي محتوى شخصي.
- 0.3.0: الإضافة السريعة بالعربية، منقولة من نسخة Windows نفسها، فتفهم «بكرة 5 العصر» و«كل خميس».
  لا تخترع تاريخاً أبداً، وتعرض الموعد قبل الحفظ، وتسألك إن كانت العبارة تحتمل معنيين.
- ثم 0.4.0 القوائم والوسوم والتقويم، و0.5.0 المهام الفرعية والقوالب، و0.6.0 استيراد التقويم والمشاركة
  والصوت، و1.0.0 الإصدار المستقر بعد 14 يوماً من استعمالك اليومي دون تأخير يُذكر.
- الرخصة: نجهّز المشروع ليكون مفتوح المصدر (Apache-2.0) دون نشر أي شيء ودون إعلان رخصة. لا يُنشر إلا
  بعد أن تقول «انشر». نسخة Windows تبقى مغلقة كما قررت.
- لا نعد بأن كل تنبيه سيصل على كل هاتف، فالشركة المصنعة وإعداداتك قد تمنعه. وعدنا أن نجدوله بدقة،
  ونكتشف ما يمنعه، ونخبرك بصراحة.
